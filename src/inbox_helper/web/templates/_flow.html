How it works From a pile of messages to a reply a person approved Watch the explainer
  1. 1 Hiring inbox Candidate messages arrive. All synthetic.

  2. Microsoft Foundry · hosted agent inbox-helper

    1. 2 Guardrail policy Blocks prompt injection before any model reads it. Blocked: to a person.
    2. 3 Classifier agent gpt-5.6-luna What does the person want? Must a person handle it? hands over: intent, confidence, reasons
    3. 4 { } Routing code A reason for a person, or under 0.70 confident: to a person. Not a candidate: set aside.
    4. 5 Drafter agent gpt-5.6-luna Writes a reply from the hiring policy only. hands over: the draft
    5. 6 { } Draft checks code 90 words or fewer, no amounts, no “!”, the right sign-off.
    6. 7 Critic agent gpt-5.5 A different model checks the draft against the policy and the message. hands back: problems, up to 2 attempts, then a person
    • Models gpt-5.6-luna, gpt-5.5
    • Guardrails content safety on the agent and on each model
    • Identity managed identity, no keys
    • Tracing a span and token count per agent step
    • Tools none granted: the agents can only return text

↓ The agent returns a proposal: the group, the reason, and a draft or none. Nothing it returns can send.

  1. 8 { } Checks again code Every draft is re-checked when it arrives here.
  2. 9 Review desk a person Approves, edits or rejects every draft. Messages for a person get no draft.
  3. 10 { } Send gate code Sends only the exact text the person approved, once.
  4. 11 Outbox simulated Every step is written to the audit trail.
